# 模特人像精修工坊｜10个虚拟角色用户视角复盘（2026-03-06）

> 目的：只站在用户视角，围绕“模特精修 = 模特锚点确认 + 套图替换精修”这条真实业务链路提出意见。
> 方法：为 10 个具体人物建模（职业、年龄、目标、工作压力、审美偏好），再让他们评价当前体验。

  - “如果当前页面没明确告诉我‘这张模特图会作为整组锚点’，我就不敢点下一步。”

## 汇总结论（用户语言）

### A. 模特工坊的真实业务定义
- 用户理解中的“模特人像精修”不是单纯修一张图。
- 真实主线是两个前后环节：
  1. 先确认一个可复用的模特锚点图
  2. 再把这个锚点应用到整组套图中，做替换与轻度精修

### B. 模特锚点页应该像什么
- 像“模特标准照确认台”，而不是“复杂参数页”。
- 默认推荐上传“全身证件照式”模特图：站姿清晰、轮廓完整、背景干净。
- 页面要明确告诉用户：
  - 这张图只负责定义“模特是谁”
  - 不负责决定整组图的背景和机位

### C. 套图替换阶段的默认原则
- 默认保留原图背景
- 默认保留原图比例
- 默认保留原图动作/姿态
- 默认只替换模特身份并做轻度精修
- “自由发挥空间”必须进入高级设置，不能抢主流程

### D. 等待反馈必须更像“生产线”
- 不能只说“执行中”
- 应显示：
  - 当前正在处理第几张
  - 已完成 / 总数
  - 是否有异常项
  - 预计还需多久（哪怕是粗略范围）

### E. 参考图顺序必须强约束
- 用户心智非常明确：
  - 1 号是主图（决定构图/姿态/场景）
  - 2 号是模特图（决定身份）
  - 之后才是其他风格参考
- 如果这个顺序不稳定，用户会直接怀疑“系统没用我的模特图”

## 对当前产品的直接修正建议
1. 把 Step2 命名成“模特锚点确认”，而不是泛化的“身份确认”。
2. 在页面首屏明确写出两阶段：`先定模特 -> 再批量替换套图`。
3. 模特锚点区默认推荐“全身标准照”，并解释原因。
4. 批量执行阶段增加更强的及时反馈：`第 X/Y 张处理中`、`已完成 N 张`、`异常 1 张`。
5. 后端强约束参考顺序：`主图 -> 模特锚点 -> 风格参考图`。
6. 在异常结果中增加“疑似未使用模特锚点”提示，帮助快速质检。
