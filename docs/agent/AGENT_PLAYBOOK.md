# Agent 工作准则（持续更新）

> 目标：少犯重复错误、提升交付质量、持续复盘改进。

## 1. 核心原则
- **不重复犯错**：错误必须记录、归因、形成可执行的防护措施。
- **一次交付可验证**：每次提交必须附验证结果（ruff/pytest/关键流程）。
- **先设计后实现**：交互/流程变更先写清楚再动代码。
- **状态可见**：任何异步动作必须有明确 UI 状态。
- **用户不做首轮排错**：问题必须先在本地复现并修复，再交付用户验证。
- **文档同步**：接口/交互/流程变更必须同步更新文档索引与对应规范。

## 2. 必做清单（每次交付）
- [ ] 运行 `ruff` + `pytest`
- [ ] 核心流程 smoke（创建→方案→生成→结果）
- [ ] 页面可导航回 `/app/tools`
- [ ] 图片/视频表单不互相混用
- [ ] OSS 直传可用：`/api/v1/oss/sign` 返回 200 + 字段齐全
- [ ] 上传不阻塞创建：创建后立即进入工作台
- [ ] “主操作”唯一，辅助操作收起
- [ ] 交互/视觉调整使用 UI/UX Pro Max 技能完成评审与输出
- [ ] 走查使用 Playwright CLI 技能执行并记录结果

## 3. 常见错误防护（更新区）
- OSS 直传签名返回字段完整性（含 `updated_at`）
- 任务创建不应被上传阻塞（先跳工作台）
- Mock 模式下异步任务要同步完成（测试稳定）
- OSS 异步持久化不得覆盖内存（避免新建项目丢失）
- 文件选择按钮必须可点击（`label + input` 方案）
- 前端不得暴露 JSON 直改，用户只编辑可读表单
- 方案生成必须异步提交（`/plan async_mode=true`）并轮询进度，禁止前端长请求卡死
- 刷新后若仍在方案阶段运行，主 CTA 保持禁用并展示“方案生成中”
- 状态文案统一中文（提交中/执行中/成功/失败），禁止英文前缀混用
- Step 1 页面保持单主动作，不出现并列主流程按钮造成决策干扰
- 工作台步骤导航固定为顶部横向进度条，禁止回退到页面左侧步骤栏挤占主操作区
- 首屏核心区（工具卡/步骤头/KPI/任务卡）必须图文并茂（矢量图标 + 精简文案），禁止大段纯文字堆叠
- UI 评审标准从“可用”升级到“可商用”：字体、背景氛围、卡片层级、按钮反馈需统一并体现高级感
- 登录页必须同时具备品牌主张、样片预览、能力摘要和明确登录收益，禁止退回成“单卡片表单页”
- 首页 Hero 必须同时承载品牌主张、主 CTA、运营样片预览和核心经营指标，禁止只剩标题+两个按钮
- 资产中台 Hero 必须同时承载操作入口、运营样片预览和资产 KPI，不得退化为“标题 + tab + 刷新按钮”
- 工作台顶部必须采用“步骤进度 + 状态摘要 + 下一步建议”三层结构，并维持统一的暖金/雾蓝卡片语义
- 工作台结果墙必须包含“结果说明 + 筛选器 + 统计卡 + 交付动作”四件套，禁止只剩素材平铺列表
- 桌面端工作台生成阶段必须优先采用“主控制区 + 侧边摘要区”双区布局，避免参数、统计、动作全部挤在一行
- 创建页表单必须采用“字段卡片化 + 说明文案 + 单主 CTA”结构，禁止回退成裸表单堆叠
- 五个工坊创建页必须存在场景差异化视觉层（头图/基调文案/能力 badge），禁止同一套头图与文案横向复用
- 工具卡、空状态、状态 banner 必须共享统一卡片语言（圆角、暖金/雾蓝边框、轻阴影），避免页面间视觉断层
- 任务卡、结果卡、工具卡内部必须采用“kicker/标题/状态或下一步/动作区”四层结构，禁止按钮直接贴在图片下方无信息缓冲
- 首页任务看板与资产中台任务列表优先使用任务卡，不优先使用表格；只有对账类信息才允许首屏表格化
- 日志抽屉必须降级为诊断层，不得在主视觉上抢占结果墙和生成控制台
- 顶栏必须采用“品牌识别 + 全局导航 + 快速搜索 + 账号状态”四段式结构，避免信息全挤成一排按钮
- 首页样片区必须采用“主打样片 + 次级样片网格 + 直接行动按钮”的运营结构，禁止纯平铺列表
- 工作台每个 Step 卡片必须包含统一抬头（STEP 标签 + 标题图标）与摘要信息条（阶段/进度/状态/下一步）
- 生成与审核步骤必须先展示控制台/摘要看板，再展示结果墙，避免用户直接落入密集素材列表
- 结果墙必须提供状态筛选（全部/已通过/待筛选/异常），大批量素材场景禁止只给单一长列表
- 运行日志必须降级为低优先级入口（默认收起 + 抽屉式查看），禁止长期占据主操作区
- 首页运营区必须同时提供“套图商品包”与“近期热销”信号位，保障运营导流和商业决策可见
- `queued` 仅表示待执行，不等于“执行中”；前端禁止把 `queued + 无plan` 渲染为“方案生成中”
- 方案生成必须具备超时兜底（默认2分钟）：超时后自动解锁主 CTA 并提示可重试
- `delivery_purpose` 属于方案必填字段：解析层、保存层、读取层都要做非空兜底，禁止页面出现空用途
- 商品棚拍结果卡必须包含可读运营文案（非“字段拼接式”），且生成结果 metadata 需保留该文案字段
- 首页样片墙只展示“主动分享”素材：禁止自动把全部生成结果灌入首页
- 分享积分必须可控：仅已入选生成图可分享，且要有每项目/每日上限防刷
- 登录名规范化：会话中若存的是邮箱，后端必须映射回标准 `username`，避免出现“已登录但角色/积分为空”
- `/api/v1/auth/me` 必须返回统一字段：`authenticated/username/role/points_balance`，前端不得自行猜测用户身份
- 计费扣分必须“先校验余额、后按成功产物扣费”，禁止按计划数量直接预扣导致误扣
- 涉及 `project_id` 的接口必须执行 RBAC 校验（admin/operator 全量，member 仅本人），禁止仅靠前端隐藏按钮
- `MASTER_TODO` 任意勾选状态变更后，必须同步刷新顶部“已完成/未完成”统计，禁止手填过期计数
- 支付/充值相关能力必须走 feature flag；未接网关前默认关闭用户端充值入口，仅保留管理员手动调分
- `MASTER_TODO` 条目从未完成改为完成时，必须在 `docs/plan/*` 写明对应冻结决策（含 v1/v1.1 边界）
- 认证链路改动必须包含：注册路径、登录风控（账号锁定/IP限流）、`auth/me` 字段回归（role/account_status/workspace/points）
- 运营闭环需求（样片墙、拍同款、质量评测、prompt评测）必须先提供后端 API 真源，再接前端交互
- 图片生成回退图（`metadata.source=original`）在生产模式下必须标记 `failed`，禁止按成功资产展示或扣费
- 本地持久化默认使用异步写盘（`MVP_STORE_ASYNC_PERSIST=true`），禁止在高频交互动作中同步全量序列化阻塞主链路
- 本地启动统一使用 `./scripts/dev_service.sh`，禁止用一次性 `nohup` 交付（会导致会话断开后进程被回收）
- 服务器发布统一使用 `systemd` 托管，必须启用 `Restart=always`，禁止手工后台跑 uvicorn
- 模特精修 Step2 主 CTA 必须置顶（生成/确认），禁止下沉到底部导致用户找不到下一步
- 批次任务卡必须区分 `当前查看` 与 `查看该图`，当前卡按钮禁用，避免“点击无变化”误判为故障
- 模特精修执行口径固定为“单任务单图产出”；方案中的修正项只做指令约束，不直接映射为产物数量
- 模特精修交互顺序固定为“先模特确认，再单图精修”；创建后默认落到身份确认步骤，不得要求用户先浏览批次要求页
- 图像/视频提示词必须走结构化编译模板（image: 主体/镜头/目标/用途/...；video: Subject/Shot/Intent/...），禁止自由散文式拼接
- 只要图模型输入包含 2 张及以上图片，提示词必须显式声明 `图1/图2/图3+` 的角色（主图/锚点图/风格参考图）；禁止只靠顺序让模型自行猜测
- `derive-prompts` 后必须产出提示词质量评分（`image_prompt_quality_avg` / `video_prompt_quality_avg`），作为可执行性检查项
- 模特精修创建后必须跳转批量工作台路由 `/app/tools/model-retouch/batches/{batch_group_id}`，不得默认落到单项目页
- 上传替换模特图也必须先处于 `identity_status=pending`，只有显式“确认锚点”后才允许批量执行
- 模特精修默认策略固定为 `keep_original + original + light`；`output_aspect_ratio=original` 必须映射为生图参数 `image_aspect_ratio=auto`
- 模特精修参考图顺序必须固定：主图作为基底输入，身份锚点作为首个参考输入，风格参考图只能排在其后，禁止让模型自行猜测身份图
- 模特锚点页必须明确表达“两阶段任务”：先定模特本人，再批量替换整组套图；默认推荐全身标准照式模特图
- 模特工坊异常结果必须在 Step3 和 Step4 同时显式提示，禁止只靠小 badge 让用户自己猜“是否命中锚点”
- OSS 直传签名中 `role=source` 必须生成唯一 object key，禁止同批次多图覆盖到同一 URL（会导致“9张都显示成同一张”）
- 模特工坊所有入口（任务列表、旧链接、搜索跳转）必须统一落到批量路由 `/app/tools/model-retouch/batches/{batch_group_id}`，禁止再暴露单项目工作台主入口
- 模特精修 Step2 必须明确三选一主动作（使用上传/精修上传/生成新模特），禁止只给“生成候选”泛化按钮
- 模特精修 Step2 必须支持“替换已上传模特图”，且替换后仍需显式确认锚点；不可自动跳过确认
- 模特精修 `use_uploaded/beautify_uploaded` 必须显式绑定“最新有效上传模特图”，禁止读取可能已切到生成候选的 `identity_asset_id` 作为上传来源
- 模特精修 Step2 必须在同页展示“创建页带入素材 + 上传模特预览 + 替换 + X移除 + 生成新模特”统一面板，禁止把关键动作拆散到多页面
- 模特精修移除上传模特图后，系统状态必须立即回到 `identity_status=pending`，并要求用户重新确认锚点后才能执行批量精修
- 任何禁用按钮必须给出可见原因（如“未上传模特图，无法使用该动作”），禁止用户感知为“点击无响应”
- 图片生成比例必须可选且默认“原图比例”；UI 显示“原图（默认）”，后端统一映射为 `image_aspect_ratio=auto`
- 当选择“原图（默认）”时，分辨率控件必须禁用，且请求中不传 `image_resolution`（禁止隐式回落固定 1K）
- 15秒短片创建页必须收敛为 5 个视频核心参数（主题/节奏/语气/CTA/时长），禁止暴露图片工坊字段（目标成片数、每镜头试拍、机位参数）
- 15秒短片提交前必须做语义映射（主题/节奏/语气/CTA -> `key_features/tone/cta_text/scene_goals`），避免后端收到空泛默认值
- 工作台步骤区的次级动作（重新生成/保存偏好/生成执行方案）必须保持 `btn-secondary`，避免与主 CTA 同权竞争
- 工作台在尚无方案/脚本/候选时，只允许展示单一主 CTA；“重新生成/执行方案”类辅助动作必须在已有内容后才出现
- 模特工坊 Step4 必须提供显式导出入口；当存在已通过结果时，主 CTA 固定为“打包下载已通过结果”
- 多角度工坊的状态文案必须与主按钮动作一致：待执行提示只能引导“保存机位/开始生成当前角度”，禁止出现“生成机位方案”这类错位术语
- 视频工坊按钮文案必须与当前真实动作一致：讲解视频在编译 prompt 前不得写“进入视频生成”，15秒短片不得复用“拍摄方案”术语
- 账务回归至少覆盖一次“部分成功、部分失败”的生成场景，验证仅按成功产物扣费
- 商品棚拍规划必须透传执行提示（`expected_shot_count/takes_per_shot/target_candidate_assets`）；高镜头数默认走“先大纲后并发逐镜头”策略，禁止只依赖单次大 JSON 返回
- 若规划结果镜头数小于目标，必须触发缺失镜头并发补齐，不允许用同质化占位提示词直接凑数交付
- 规划模型默认使用 `doubao-seed-2-0-mini` 且关闭深度思考（`thinking=disabled`）；若修改模型档位，必须同时给出时延评估和回退方案
- VL 模型调用必须带候选回退链：当出现 `InvalidEndpointOrModel.NotFound` 时自动切换备用模型，禁止首选模型不可用时直接把 404 暴露给用户
- 商品棚拍结果页默认以“批量交付”动线为主（批量入选/批量分享/打包下载），单张按钮仅在手动模式展示，禁止默认满屏逐张操作按钮
- 前端 hooks 相关变量必须“先声明后引用”：禁止在 `useEffect/useMemo/useCallback` 逻辑或依赖数组里引用后置 `const`，提交前必须排查 TDZ 风险
- 批量生成链路必须保证“预期任务数 = 终态资产数（成功+失败）”；若外部模型超时或缺返回，后端必须落库失败资产并给出可重试入口，禁止用户无限等待
- 登录页不得使用“单卡片纯表单”默认样式交付；必须包含品牌海报区、摄影预览图、主次 CTA 分层和可见状态反馈
- 首页样片墙图片加载策略必须为“本地可持久路径优先 + onError 自动回退 + 静态兜底图”，禁止依赖临时 URL 导致破图
- Topbar 交互元素必须使用紧凑尺寸（小按钮/小芯片/短搜索），禁止把全局导航做成大 CTA 风格造成视觉拥挤
- Topbar 与首页文案必须是产品语言，禁止展示“状态码字段/工作空间ID”等开发语义
- 首页首屏 KPI 必须分层：核心指标卡优先，次级指标用 compact chips 展示，禁止全部指标同权重平铺
- 模特 Step2 必须采用“模式选择 + 单主动作”结构（使用上传/精修上传/生成新模特），禁止同时暴露多个并列主动作按钮
- 资产相关能力必须统一落在“资产中台”内（任务/素材/样片三视图），禁止把任务流和素材流拆成彼此割裂的导航终点
- 视觉升级场景优先用“舞台化容器 + 卡片轨道 + 控件减量”策略，避免回退到表格/字段主导的后台观感
- 首页/资产/工具创建页必须提供“继续上次任务”入口，回访路径优先级不得低于“新建任务”
- 五工坊创建页首屏必须有“本次产出预期卡”（产出数量/预计耗时/交付形式），禁止以纯表单作为首屏主内容
- 工具任务区默认结构必须是“优先队列（卡住/待确认/执行中）+ 最近3条 + 全量折叠查看”，禁止默认全量长表
- 所有用户可见图片（首页/资产/工作台）必须配置 `onError` 兜底，且 fallback 不得为空；无兜底视为阻断发布问题
- 积分中心首屏必须先展示“余额/可用天数/近7天收支”，订单与流水明细默认折叠，禁止首屏长表压屏
- 用户管理默认视图必须是“异常账号优先”，并保留“待处理/全部”切换；禁用/提权等高风险操作必须二次确认
- 工作台任一步骤仅允许一个主 CTA；同层其他动作必须降级为 secondary/ghost，禁止并列多个 primary
- 所有异步状态文案必须使用统一中文阶段词（提交中/执行中/成功/失败），禁止 `uploading/warning` 等英文前缀进入用户界面
- 讲解视频工坊 Step2 必须“脚本预览前置”为主视觉（候选脚本 + 镜头摘要），主 CTA 固定为“确认主脚本并进入视频生成”
- 模特批次工作台 Step3 必须按状态分栏展示（待确认/执行中/待审核/可导出），禁止无分组平铺
- 模特批次统计口径必须把 `reviewing` 计入“执行完成”，禁止把“待审核”误算为“排队中”导致用户误判卡死
- 模特批次“执行中”列只允许真实运行/排队任务；无结果且非运行任务必须落到“待审核/异常处置”并提供可点击重试
- 批量执行页必须展示“自动刷新状态 + 手动刷新按钮 + 超时提示（建议重试）”，禁止只给静态计数
- 任务中心/首页看板/资产任务卡必须同时展示“风险标签 + 下一步提示”，禁止只展示阶段和状态
- 资产中台用户可见字段必须是产品语言（如“用户上传/AI生成/任务编号/处理状态”），禁止直接暴露 `uploaded/generated/kind/project_id` 等后端枚举
- 积分中心必须提供“经营结论”层（节省工时/产出规模/风险等级），禁止只给流水明细
- 设计评审文档必须“页面级 + 多轮次”输出（R1观感、R2动线、R3文案心智、R4商业风险），每轮都要有具体页面证据，禁止抽象吐槽
- 面向互联网产品的 UX 评审必须先做 Persona 建模（至少 10 类用户，包含职业/年龄/兴趣/设备/场景/目标），禁止只用单一“泛用户”视角
- 每轮交互改版必须产出 Persona × 页面优先级矩阵（P0/P1/P2），并据此冻结本轮范围，禁止边做边改导致目标漂移
- 交付前至少验证 3 个核心 Persona 的关键路径（新手运营 / 内容创作者 / 交付经理），并在文档记录结论
- Persona 吐槽必须故事化表达（人物 + 场景 + 目标 + 阻塞 + 情绪），禁止只输出“问题清单式”抽象结论
- Persona 故事化吐槽输出后必须同步转成“执行改造单”（页面 + 组件 + DoD + 指标），否则不得进入开发排期
- 需求文档必须先输出 ISO 风格框架（章节、编号、追踪关系）再填充细节内容，禁止直接写散点需求
- 每个需求条目必须具备 Requirement ID、shall 语句、优先级、验收方式；缺任一项不得进入开发
- 需求冻结后必须输出 FR 追踪矩阵（FR -> 代码 -> 测试 -> 状态），禁止只停留在需求描述层
- 关键模块必须补充业务逻辑决策表（条件/动作/例外），禁止仅用自然语言叙述复杂逻辑
- 需求细化必须下沉到字段级规格（字段键/默认值/校验/API映射/错误提示），缺字段级规格不得进入开发排期
- 所有验收用例必须进入统一 AT Catalog（AT ID、步骤、自动化状态、证据路径），禁止在不同文档重复定义不一致编号
- 每个 PR 必须声明 FR ID + AT ID + 自动化状态变化，缺任一项视为未完成交付

## 4. 复盘与更新

- 防护措施写入本准则
- 每次复盘需补充“如何避免二次发生”的自动化或流程约束
