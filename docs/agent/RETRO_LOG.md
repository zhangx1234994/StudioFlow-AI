# 错误复盘日志（持续追加）

> 记录格式：日期 / 问题 / 根因 / 修复 / 防护措施

## 2026-03-02
- 问题：点击创建任务报错（OSS签名缺字段）
  根因：`/api/v1/oss/sign` 返回缺少 `updated_at`，导致响应模型校验失败。
  修复：补齐 `updated_at` 字段。
  防护：新增“接口返回字段与 schema 一致性”检查。

- 问题：新建项目后找不到（OSS 异步持久化覆盖内存）
  根因：启用 OSS 异步持久化时，读取接口仍会从远端覆盖本地状态。
  修复：异步持久化时跳过远端 sync。
  防护：在 store 层增加“异步持久化禁止同步覆盖”规则。

- 问题：mock 模式下脚本为空导致脚本选择失败
  根因：intro bootstrapping 走异步导致 create 返回时 script_options 为空。
  修复：mock 模式同步执行 bootstrap。
  防护：mock 模式严格同步，保证测试用例稳定。

## 2026-03-04
- 问题：点击“生成AI方案/生成拍摄方案”后请求长时间无返回，页面看起来卡死。
  根因：`/plan` 默认同步执行，前端在慢模型链路上被阻塞；刷新后也未正确识别“方案仍在运行”。
  修复：`/api/v1/projects/{id}/plan` 支持 `async_mode`，前端默认异步提交并轮询；运行中主按钮禁用并显示“方案生成中”。
  防护：进度提示文案在 `plan + running` 时统一显示“生成中”，失败时自动退出 pending 状态并给出错误提示。

- 问题：状态提示中英文混用、Step1 引导与按钮不一致，用户难以判断下一步。
  根因：前端历史文案使用 `submitting/running/success/failed` 前缀，且默认引导文案未按工具区分。
  修复：全站工作台状态前缀改为中文；Step1 默认引导改为按工具输出（拍摄方案/精修方案/机位控制/一键继续）。
  防护：将“状态文案中文化”和“Step1 单主动作”写入 AGENT_PLAYBOOK 强制约束。

- 问题：工作台本地流程区放在左侧，压缩主操作区域，用户在内容页编辑和查看结果空间不足。
  根因：沿用了旧版双栏布局（`page-grid + side-stepper`），没有将步骤导航与主内容优先级对齐。
  修复：移除左侧步骤栏，改为顶部横向“流程进度”步骤条，保留步骤可点击切换与当前/已完成态。
  防护：在交互契约与 AGENT_PLAYBOOK 中新增硬约束：工作台步骤导航必须顶部横向展示，禁止回退左侧流程栏。

- 问题：首页与工作台首屏信息以纯文本为主，阅读负担重，视觉层级不够。
  根因：缺少统一图标系统与信息密度控制规则，导致标题、卡片、指标区文本堆叠。
  修复：新增统一矢量图标组件并应用到导航、工具卡、KPI、工作台流程与核心信息卡；工具描述区做两行截断控制。
  防护：将“核心区图文并茂（图标 + 精简文案）”写入交互契约与 AGENT_PLAYBOOK 强制约束。

- 问题：整体观感停留在“工具可用”层级，缺少商业化产品需要的高级质感。
  根因：全局视觉 token 与组件材质没有统一升级，字体、背景、卡片、按钮缺少品牌化风格体系。
  修复：完成一轮视觉系统升级（字体替换、背景氛围层、卡片材质与阴影、按钮动效、表格与状态条层级）。
  防护：在交互契约与工作准则加入“可商用高级感”标准，后续 UI 交付必须按视觉系统检查而非只看功能。

- 问题：样片区虽然有图片，但仍偏“素材列表”，缺少运营首页应有的主次叙事与强引导。
  根因：样片布局为同权重卡片平铺，首屏缺少“主打案例位”与行动焦点。
  修复：首页样片区改为“主打大图案例 + 次级案例网格 + 直达 CTA”，并把空态改为可行动引导块。
  防护：在交互契约与 AGENT_PLAYBOOK 固化首页样片运营结构，避免回退到纯平铺样式。

- 问题：工作台步骤内容虽然功能完整，但视觉结构仍像“连续表单块”，步骤感和方向感不足。
  根因：缺少统一 Step 抬头体系与项目级摘要信息条，用户进入每步后需要重新阅读上下文。
  修复：新增 Step 头（STEP 标签 + 图标 + 标题）与工作台摘要信息条（阶段/进度/状态/下一步），步骤导航 chip 增加流程图标。
  防护：把工作台 Step 面板结构写入交互契约与 AGENT_PLAYBOOK，作为后续改版验收硬标准。

- 问题：生成和审核阶段仍以素材列表为主，参数调整与结果决策信息没有前置，认知切换成本高。
  根因：缺少“控制台/摘要看板”层，用户需要在结果墙中自行拼接关键指标。
  修复：生成阶段新增控制台卡与结果指标卡；审核阶段新增总览摘要卡（总产物/已通过/待审核/异常）。
  防护：将“先控制台后结果墙”的结构写入交互契约与 AGENT_PLAYBOOK，作为工作台验收标准。

- 问题：大批量结果进入“试拍/审核”后只能长列表滚动，定位低通过项与异常项效率低；日志仍可能抢占操作注意力。
  根因：结果墙缺少状态筛选器和镜头维度聚合；日志虽折叠但仍是同层内容块，视觉权重偏高。
  修复：生成与审核阶段新增统一筛选器（全部/已通过/待筛选/异常），商品棚拍结果墙升级为“镜头信息 + 候选轨道 + 状态统计”；日志改为抽屉式低优先级入口。
  防护：在交互契约与 AGENT_PLAYBOOK 增加硬规则：结果墙必须可筛选，日志默认抽屉式降权，禁止回退到密集长列表与大块日志布局。

- 问题：首页运营区虽有套图包，但缺少“近期热销”信号，不利于用户快速判断热卖方向。
  根因：运营模块只做静态商品包列表，缺少横向决策信息位。
  修复：新增“近期热销”面板，与套图包并列呈现，支持一键跳转对应工坊。
  防护：将“套图商品包 + 热销信号位”写入交互契约与工作准则，作为首页商业化验收项。

- 问题：工作台在 `task_status=queued` 且 `project_plan` 为空时，主按钮被误锁成“方案生成中”，用户无法再次触发生成，页面可卡几十分钟。
  根因：前端把 `queued` 当成“正在生成”，并且缺少计划生成超时解锁机制。
  修复：`isPlanLoading` 改为仅在 `running+plan阶段` 或 `pendingPlanRef` 时生效；新增2分钟超时兜底，超时后自动解锁并提示重试。
  防护：在 AGENT_PLAYBOOK 增加硬规则：`queued != running`，且方案生成必须带超时兜底。

- 问题：方案生成后部分镜头“预期用途（delivery_purpose）”为空，导致工作台内容缺失。
  根因：VL 返回空白字符串时，解析逻辑先命中 `delivery_purpose` 字段再 `strip`，没有继续回退默认用途。
  修复：解析层新增 `delivery_purpose` 归一化（过滤空白/null/none 等占位值）；生成、保存、读取项目时统一补齐用途；前端展示层增加场景兜底用途显示。
  防护：提示词 schema 与 hard_rules 强制要求 `delivery_purpose`；新增 API/服务回归用例覆盖空用途补齐。

- 问题：商品棚拍试拍速度偏慢，且候选图卡片文案过于机械（仅“用途+卖点”），不利于电商运营选图。
  根因：图片任务默认并发仅 2；结果卡片只拼接基础字段，没有面向运营的说明文案。
  修复：将图片生成默认并发提升到 4（上限 8，按任务量自动收敛）；生成资产 metadata 新增 `marketing_copy`，前端优先展示运营文案。
  防护：回归用例新增断言（`delivery_purpose` 与 `marketing_copy` 必须存在），避免再次回退到无文案状态。

- 问题：商品棚拍最后一步“选片定稿”偏内部流程语言，不利于运营闭环；首页样片墙缺少用户主动贡献机制。
  根因：审核通过与首页展示未打通，结果页缺少“分享”动作与激励反馈。
  修复：将商品棚拍 Step4 重命名为“选片分享”；新增 `/api/v1/projects/{id}/share`，支持把已入选图片推送到首页样片墙并发放分享积分。
  防护：分享动作增加门禁（仅已入选生成图可分享）与积分上限（每项目最多5张、每日最多50分）；首页样片墙只读取 `showcase_shared` 标记，避免自动灌入低质量内容。

- 问题：用户管理、积分、充值功能缺失，且登录态偶发显示“已登录但角色/积分为空”。
  根因：业务层缺少账户与计费实体；本地登录只依赖环境变量管理员；历史会话可能存的是邮箱，前端无法映射到用户档案。
  修复：新增用户与计费模型（User/Recharge/Ledger），补齐 `/api/v1/users` 与 `/api/v1/billing/*` 接口；本地登录改为用户仓库鉴权；`/api/v1/auth/me` 返回 `role/points_balance`；登录名统一做 `email -> username` 归一化。
  防护：在 AGENT_PLAYBOOK 增加“auth/me 字段统一 + 登录名归一化 + 先校验后扣费”规则，并把用户/积分接口写入 `docs/api-contract.md`。

- 问题：生成扣费逻辑之前未打通，无法支撑商业化收费闭环。
  根因：只有任务执行状态，没有统一的积分预检、扣费、奖励入账逻辑。
  修复：图片生成按成功张数扣费（1 point/asset），视频按成功候选数扣费（10 points/variant）；生成前余额预检；样片分享奖励写入积分流水。
  防护：新增 API 回归用例覆盖“充值创建与确认、手动调分、本地账号登录”，并在交付检查中固定执行。

- 问题：多用户场景缺少项目级权限隔离，成员理论上可读到他人任务。
  根因：此前只有登录态，没有基于 `owner_username + role` 的访问控制层。
  修复：新增 v1 RBAC（admin/operator/member）与项目归属校验；项目详情、进度、生成、审核、资产等接口统一做权限校验；列表接口对 member 自动过滤。
  防护：新增回归用例 `test_member_project_permission_isolation`，强制验证“成员不能访问他人项目”。

- 问题：`MASTER_TODO` 顶部进度统计与实际勾选项不一致，导致优先级判断偏差。
  根因：多轮并行更新后只改了条目状态，未同步校对汇总计数。
  修复：重新按复选框统计并更新为 `73/91`，补充 P0/P1/P2 剩余项总览。
  防护：后续每次更新 ToDo 勾选项必须同步执行自动计数校验，再写入顶部“当前进度”。

- 问题：充值能力当前阶段不应对用户开放，但页面仍显示“提交充值申请”，与运营策略不一致。
  根因：计费中心沿用了早期占位流程，没有按“管理员手动加分、充值接口预留”策略收敛。
  修复：充值创建/确认接口增加开关并默认关闭（返回 503）；积分中心改为明确展示“充值通道预留”，主流程改为管理员积分调整。
  防护：所有支付/充值入口必须受 feature flag 管控，未对接支付网关前默认隐藏前台入口。

- 问题：账号体系缺少公开注册与登录风控，存在暴力尝试风险，且 Workspace/账号状态模型未落地。
  根因：早期只覆盖管理员登录与后台建号，未完成“注册 + 风控 + 账号状态”闭环。
  修复：新增本地注册接口 `/api/v1/auth/register`；登录增加账号锁定与 IP 限流；用户模型新增 `workspace_id` 与 `account_status` 并写入鉴权返回。
  防护：认证相关改动必须同时补充 API 文档、回归用例（注册/锁定/状态字段）和前端登录页状态提示。

- 问题：样片墙“拍同款”仅跳转工具页，缺少可追踪的同款创建链路；质量与提示词缺少运营可视指标接口。
  根因：运营流与算法评测流停留在页面层，未抽象为后端公共 API。
  修复：新增 `/api/v1/showcase/assets` 与 `/api/v1/showcase/remix`，支持基于样片一键创建同款项目并记录来源；新增 `/api/v1/quality/summary` 与 `/api/v1/prompts/metrics` 供运营和算法评测使用。
  防护：涉及“运营看板/评测看板”的需求必须优先沉淀 API，再做页面交互，避免再次出现“只有 UI 没有数据链路”。

- 问题：样片墙“拍同款”按钮全部显示“创建中”且不可点击。
  根因：按钮 loading 状态直接比较 `remixingAssetId === assetId`，当两者都为空字符串时被误判；同时样片列表误用 `kind=image` 过滤，导致 assetId 长期为空。
  修复：loading 条件改为 `assetId 非空且与 remixingAssetId 相等`；样片过滤改为 `kind=generated_image`。
  防护：涉及异步按钮 loading 的判断必须包含“实体存在”前置条件，并在 Playwright 回归中覆盖“空数据态按钮可点击性”。

- 问题：用户最近任务中“多张结果图看起来完全一样”。
  根因：生图链路在模型调用失败时会回退到原图（`source=original`），但资产仍被标记为 `ready`，导致前端误判为“生成成功”。
  修复：图片资产仅在 `source=generated` 时记为 `ready`；生产模式下回退图统一标记 `failed` 并暴露重试；增加 KIE `createTask/recordInfo` 失败详情日志（含状态码与响应片段）与重试。
  防护：新增规则“回退图不得记为成功资产”；文档明确 mock/生产模式差异；交付前检查最近任务 `metadata.source` 分布，若全为 `original` 直接阻断交付。

- 问题：选片页“入选/分享到首页”点击后反馈慢。
  根因：本地存储模式每次状态变更都会同步序列化全量 `store.json`（项目/素材/日志全量），数据量增大后单次点击被阻塞。
  修复：为本地存储开启异步持久化（默认开启），把全量写盘改为后台线程节流写入，不阻塞接口响应。
  防护：新增 `MVP_STORE_ASYNC_PERSIST` 开关，生产默认开启；若需要强一致写盘可显式关闭。

- 问题：服务频繁“看起来启动了，但很快又掉线”，导致前端出现 `Failed to fetch` 和“点击无响应”。
  根因：使用临时后台命令启动（会话结束后进程被回收），没有进程守护和健康检查。
  修复：新增 `scripts/dev_service.sh`（screen 常驻 + 健康检查 + 标准化 up/down/restart/status/logs）；新增 Linux `systemd` 模板 `deploy/systemd/studioflow-ai.service`（`Restart=always`）。
  防护：本地/交付环境统一走服务托管脚本，禁止手工 `nohup`；服务器必须使用 `systemd` 托管并启用自动重启。

- 问题：模特精修 Step2 主操作按钮位置过低、批次卡“切换查看”语义模糊，用户误判为无响应。
  根因：Step2 先渲染批次卡和方案内容，再渲染主 CTA；同页点击当前任务时无路由变化，缺少状态区分。
  修复：Step2 顶部前置主 CTA（生成/确认）；批次卡按钮改为 `当前查看/查看该图`，当前卡按钮禁用并高亮说明。
  防护：在交互契约与工作准则中新增“Step2 顶部主 CTA + 当前任务禁用查看按钮”硬约束。

- 问题：模特精修用户上传 N 张图后，单任务生成常出现 4 张候选，和“1图=1任务”认知不一致。
  根因：精修方案内多个修正项被当作独立 prompt 全部执行，导致每个任务按“修正项数”出图。
  修复：模特精修生成阶段改为“单图单结果”模式（默认仅执行首个编译 prompt）；进度目标资产改为 1（每任务）。
  防护：模特精修链路统一遵循“批次拆任务、单任务单图”的执行原则，避免再把方案修正项当作产物数。

- 问题：模特精修上传后先进入“批次精修要求”页面，用户期望是先确认模特（精修上传模特或生成新模特），该页造成认知噪音。
  根因：工作台默认将 `plan/prompt` 阶段都映射到 Step2（批次精修要求），没有按模特业务优先级重排。
  修复：模特精修主流程改为创建后优先进入“身份确认”，Step2 页面从主流程移除；首页主 CTA 改为“进入模特确认”。
  防护：模特精修流程固定为“身份确认优先”，不得回退到先看批次卡再确认模特的路径。

- 问题：图像/视频提示词虽然可用，但结构不稳定，难以持续评估“是否足够可执行、是否满足模型约束”。
  根因：编译阶段主要做清洗和拼接，缺少统一结构模板和质量评分回传。
  修复：提示词编译器升级为结构化模板输出（image/video 分别固定字段）；新增编译质量评分并回写 `guardrail_report.image_prompt_quality_avg/video_prompt_quality_avg`。
