1. 逐条读取 FR（Requirement ID）。

## 3.2 批量分栏逻辑（冻结）

```text
if identity_status != confirmed -> 待确认
else if task_status in {queued, running, rendering} -> 执行中
else if task_status in {failed, error} or generated_count == 0 -> 待审核（异常处置）
else if pending_count > 0 or failed_count > 0 -> 待审核
else -> 可导出
```

## 3.3 参数规则（冻结）

1. 默认 `output_aspect_ratio=original`。
2. 当 `output_aspect_ratio=original` 时，前端分辨率控件禁用，后端请求不传 `image_resolution`。
3. 默认策略：`keep_original + original + light`。

## 3.4 API 级细化

| 接口 | 必传 | 关键响应字段 | 错误处理 |
|---|---|---|---|
| `GET /batches/{id}` | batch_group_id | total/done/failed/running/queued/identity_status/projects | 404 显示“批次不存在” |
| `POST /identity/generate-candidate` | identity_source | identity candidate 资产可见 | 400 展示具体原因 |
| `POST /identity/confirm` | asset_id | identity_status=confirmed | 未确认前不得进入 Step3 |
| `POST /generate` | async_mode | 批次状态即时返回 | 失败时可点重试 |
| `POST /retry` | 可选 project_ids | 重试后 running/queued 更新 | 失败显示单任务重试错误 |
