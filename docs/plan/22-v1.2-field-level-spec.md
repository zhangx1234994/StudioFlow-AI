## 1. 统一规范

## 1.1 统一状态词（用户可见）
- `提交中`：请求已发送，等待后端受理。
- `执行中`：后端任务已运行，等待完成。
- `成功`：任务达到可继续下一步的终态。
- `失败`：本步骤失败，必须给出可重试入口。

## 1.2 统一错误码（前后端对齐）

| Code | 用户文案 | 处理动作 |
|---|---|---|
| `INVALID_CREDENTIALS` | 账号或密码错误 | 保持当前页，聚焦账号输入框 |
| `SESSION_EXPIRED` | 登录状态已过期，请重新登录 | 跳 `/app/login` 并保留返回路径 |
| `NETWORK_ERROR` | 网络异常，请检查连接后重试 | 显示重试按钮，不清空已填内容 |
| `SERVER_ERROR` | 服务繁忙，请稍后再试 | 保留上下文 + 记录 `request_id` |
| `INVALID_INPUT` | 输入信息不完整或格式错误 | 标记具体字段错误 |
| `INSUFFICIENT_BALANCE` | 积分不足，请联系管理员充值 | 跳积分页并高亮余额卡 |
| `PERMISSION_DENIED` | 无权限访问该任务 | 返回 `/app/tools` |

## 1.3 单步主 CTA 规则
- 每步只允许 1 个 `primary` 按钮。
- 同层其他动作只能是 `secondary/ghost`。
- `primary` 在 `提交中/执行中` 必须禁用，文案切换为进行中状态。

## 2. 创建页公共字段（五工坊通用）

| 字段键 | 页面文案 | 类型 | 默认值 | 必填 | 校验 | API 映射 |
|---|---|---|---|---|---|---|
| `project_name` | 任务名称 | string | 自动生成 | 否 | 1-80 字符 | `name` |
| `delivery_purpose` | 产出用途 | enum | `commerce` | 是 | 枚举内值 | `delivery_purpose` |
| `target_final_count` | 最终成片数 | int | `4` | 是 | `1-60` | `target_final_count` |
| `source_urls` | 主素材组图 | string[] | `[]` | 是 | 至少 1 张，可撤回 | `source_image_urls` |
| `reference_model_url` | 模特参考图 | string | `null` | 否 | URL 可访问 | `reference_image_url` |
| `advanced_options` | 高级设置 | object | `{}` | 否 | 各工具子规则 | `tool_config` |

### 公共边界规则
1. 主素材必须“前端直传 OSS”完成后才允许提交创建。
2. 创建成功后必须立即路由到工作台，不等待后续模型任务。
3. 同批次多图上传的 URL 必须唯一，不得覆盖。

## 3. 商品棚拍出图工坊（Product Image Studio）

## 3.1 Step1 需求与素材

| 字段键 | 文案 | 默认值 | 约束 | API |
|---|---|---|---|---|
| `shoot_style` | 拍摄风格 | `clean_studio` | 枚举 | `tool_config.shoot_style` |
| `camera_mood` | 镜头氛围 | `commercial` | 枚举 | `tool_config.camera_mood` |
| `target_final_count` | 最终成片数 | `4` | `>= shots * takes_per_shot` | `target_final_count` |
| `takes_per_shot` | 每镜头候选数 | `2` | `1-4` | `tool_config.takes_per_shot` |

## 3.2 Step2 拍摄方案

| 字段键 | 文案 | 默认值 | 约束 | API |
|---|---|---|---|---|
| `shot_count` | 镜头数量 | 自动推导 | `1-30` | `plan.expected_shot_count` |
| `planner_mode` | 生成策略 | `outline_then_expand` | 高镜头数强制两段式 | `plan.strategy` |
| `plan_timeout_sec` | 超时阈值 | `120` | 超时必须解锁重试 | 前端控制 |

### Step2 规则
1. 若目标镜头数 > 12，必须走“先大纲后并发逐镜头补齐”。
2. 若返回镜头数不足，必须自动补齐缺失镜头，不允许直接交付。
3. 按钮文案：`生成拍摄方案` -> `方案生成中...` -> `方案已生成`。

## 3.3 Step3 开始试拍

| 字段键 | 文案 | 默认值 | 约束 | API |
|---|---|---|---|---|
| `output_aspect_ratio` | 输出比例 | `original` | 原图模式不传分辨率 | `generation.output_aspect_ratio` |
| `image_resolution` | 分辨率 | `1K` | `original` 时禁用 | `generation.image_resolution` |
| `retry_failed_only` | 仅重试失败项 | `true` | 可切换 | `retry.scope` |

## 3.4 Step4 选片分享
- 默认主路径：批量入选 -> 批量分享 -> 打包下载。
- 单张入选/淘汰仅在“手动模式”显示。

## 4. 模特人像精修工坊（Model Retouch Studio）

## 4.1 Step1 素材确认

| 字段键 | 文案 | 默认值 | 约束 | API |
|---|---|---|---|---|
| `source_urls` | 待精修组图 | 来自创建页 | N 张展示 N 张 | `batch.projects[].source_image_url` |
| `uploaded_identity_url` | 上传模特图 | 可选 | 可替换、可移除 | `identity.uploaded_asset_url` |

### Step1 规则
1. 上传 9 张必须展示 9 张，不得重复同一 URL。
2. 移除上传模特图后，状态必须重置为 `identity_status=pending`。

## 4.2 Step2 模特锚点确认台（核心页）

| 字段键 | 文案 | 默认值 | 约束 | API |
|---|---|---|---|---|
| `identity_mode` | 模式选择 | `use_uploaded` | 三选一：使用上传/精修上传/生成新模特 | 前端状态 |
| `identity_prompt` | 新模特描述 | 空 | 仅 `generate_new` 可编辑 | `identity.generate.prompt` |
| `framing_preset` | 模特景别 | `full_body` | 针对锚点，不改组图构图 | `identity.generate.framing_preset` |
| `preserve_pose` | 保留姿态 | `true` | 仅生成新模特模式可调 | `identity.generate.preserve_pose` |
| `identity_anchor_asset_id` | 当前锚点 | `null` | 未确认前禁止进入 Step3 | `identity.confirm.asset_id` |

### Step2 交互规则
1. 顶部仅 1 个主 CTA，页面必须明确表达“两阶段任务：先定模特本人，再替换整组套图”。主 CTA 文案按模式动态切换：
   - 使用上传：`直接使用上传模特图`
   - 精修上传：`精修上传模特图`
   - 生成新模特：`生成新模特候选`
2. 必须有“当前锚点总览”卡，明确显示当前确认对象。
3. 默认推荐上传全身标准照式模特图，用于稳定锁定身份、发型和体型比例。
4. 若参数与上次一致且无新结果，返回“当前候选未变化（参数相同）”。

## 4.3 Step3 批量精修执行

| 字段键 | 文案 | 默认值 | 约束 | API |
|---|---|---|---|---|
| `background_policy` | 背景策略 | `keep_original` | 默认保留原背景 | `batch.generate.background_policy` |
| `output_aspect_ratio` | 输出比例 | `original` | `original -> image_aspect_ratio=auto` | `batch.generate.output_aspect_ratio` |
| `retouch_strength` | 精修强度 | `light` | 默认轻度保真 | `batch.generate.retouch_strength` |
| `concurrency` | 并发度 | 自动 | 由后端按 QPS 控制 | 服务层 |

### Step3 规则
1. 批量页必须可见所有任务卡（N 张即 N 卡）。
2. 执行中页采用流式回填，禁止整批无反馈等待。
3. `reviewing` 计入已完成；执行中列仅显示 `queued/running/rendering`。

## 4.4 Step4 结果审核与导出
- 分栏：`待审核 / 可导出 / 异常`。
- 主 CTA：`导出已通过结果`。
- 异常卡必须提供 `重试该任务`。

## 8. 状态机与边界事件

## 8.1 前端状态机
- `booting -> unauthenticated -> authenticating -> authenticated -> error`
- 任意异常都必须落入 `error` 且可重试。

## 8.2 生成任务终态
- 成功终态：`ready/reviewed/rejected`
- 失败终态：`failed/error`
- 禁止“无终态任务”长期停留在 `running`。

## 8.3 超时策略
1. 方案生成超时（120s）后，按钮解锁并提示“可重试”。
2. 批量生成单项超时必须写入失败资产，避免用户无限等待。
