# 01 商业模型与收费设计（P0 冻结版）

## 1) 收费对象与口径（冻结）
- 图像工具：按成功生成产物扣费（当前 `1 point / 张`）。
- 视频工具：按成功候选扣费（当前 `10 points / 条`，15 秒为标准候选）。
- 试拍与方案阶段：不扣费（只做方案确认和质量预览）。

## 2) 失败/重试/放弃扣费规则（冻结）
- 模型失败、超时、风控拒绝：不扣费。
- 系统异常导致已扣费但无产物：自动冲正（写入 `manual_adjust` 或 `system_refund` 流水）。
- 用户主动重生成：按成功产物正常扣费。
- 用户中途放弃（未触发生成）：不扣费。

## 3) 价格梯度（标准/高级/旗舰）
- Standard：默认档，平衡速度与成本（倍率 `1.0x`）。
- Advanced：质量优先，使用更高质量参数（倍率 `1.4x`）。
- Premium：最高质量与最高稳定性（倍率 `1.9x`）。

说明：
- 倍率作用在“基础扣点”上，例如图像基础 1 point，在 Premium 档为 1.9 points（向上取整）。
- 当前先冻结规则和展示，不强制立即切换所有工具 UI。

## 4) SLA 与价格挂钩（冻结）
- Standard：普通队列，目标 `T90 <= 120s`（图像）/ `<= 12min`（视频）。
- Advanced：优先队列，目标 `T90 <= 90s`（图像）/ `<= 10min`（视频）。
- Premium：最高优先级，目标 `T90 <= 60s`（图像）/ `<= 8min`（视频）。

超时策略：
- 超过各档 SLA 的任务可触发补偿积分（按规则比例返还）。

## 5) 试用策略（冻结）
- 新用户注册赠送 `60 points`（可配置）。
- 试用期可用全工具，但限制高级档（Advanced/Premium）调用次数。
- 首次分享样片额外奖励 `10 points`（与分享奖励策略合并计算）。
- 试用余额不足时引导到积分中心，不弹支付（当前充值通道预留）。

## 6) 结算逻辑（冻结）
- 生成前余额校验，不足即阻断并返回明确提示。
- 扣费记录必须写入积分流水（含 `project_id`、`kind`、`delta`、`balance_after`）。
- 订单关闭：连续 30 天无活动且余额为 0 的测试账号可标记为 dormant（不删数据）。
- 退款口径：
  - 系统责任：自动或管理员手动返还。
  - 用户主观质量争议：管理员审核后手动返还。

## 7) 当前充值策略（已执行）
- 充值接口先预留：`/api/v1/billing/recharge` 与 `/confirm` 默认关闭。
- 当前由管理员通过 `/api/v1/billing/adjust` 给注册账号加积分。
- 后续支付网关接入后再开放在线充值。

## 8) 待实施项（代码）
- 价格档位倍率与 SLA 配置中心化（按工具可覆盖）。
- 补偿积分自动化（超时与失败归因自动判定）。
- 支付网关接入与充值订单闭环。
